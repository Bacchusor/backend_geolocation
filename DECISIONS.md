# Decisions

Defaults chosen while building GeoReminder, with the reasoning. Change a decision here first, then in the code.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                         | Why                                                                                                                                                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Monorepo with pnpm workspaces**: `apps/api` (Fastify), `apps/admin` (React/Vite), `packages/shared` (zod schemas + types). The shared package is built to `dist` and consumed as a normal dependency.                                                                                                                                                                                                          | Both apps validate with the same schemas; a built package keeps the Docker builds simple.                                                                                                            |
| 2   | **Drizzle ORM + hand-written SQL migrations** in `apps/api/drizzle/` (generated once with drizzle-kit, then edited: PostGIS extension, GiST indexes). Migrations run automatically on API start through Drizzle's migrator (idempotent, tracked in `__drizzle_migrations`). No down migrations: rollback = restore the `pg_dump` taken before an upgrade.                                                        | Drizzle has no down migrations; at this scale a backup-based rollback is simpler and safer than maintaining reverse SQL.                                                                             |
| 3   | **Spatial columns are `geography(Point,4326)`** with a GiST index; every candidate query uses `ST_DWithin` in the `WHERE` clause and `ST_Distance` only for ordering. Coordinates are parsed from EWKB on read.                                                                                                                                                                                                  | Correct distances on the sphere without a projection choice; index-friendly.                                                                                                                         |
| 4   | **Rule semantics**: a rule attaches to a place _or_ a place group, has one trigger, and a list of recipients. It evaluates for the person of each recipient and notifies _that person's_ recipients only.                                                                                                                                                                                                        | Matches the family use case ("the person approaching the shop gets the reminder") and keeps the data model flat.                                                                                     |
| 5   | **Geofence state machine per person × place** (`place_states`): approach/enter tiers with exit hysteresis (`radius × 1.25`, configurable), dwell fired once per stay. A fix whose accuracy exceeds a tier's radius cannot change that tier.                                                                                                                                                                      | Prevents flapping at the boundary and false triggers from coarse fixes; pure function, unit-tested.                                                                                                  |
| 6   | **Cooldown and daily cap are derived from the event log** (`rule_events` with outcome `notified`), not from extra counters. Daily cap resets at local midnight in `TZ`.                                                                                                                                                                                                                                          | One source of truth; the log is needed anyway.                                                                                                                                                       |
| 7   | **Plausibility**: reject fixes from the future, older than `MAX_FIX_AGE_HOURS`, older than the stored current position (out of order), or implying > `MAX_SPEED_MPS` within a 1 h window. After a gap ≥ 1 h any jump is accepted.                                                                                                                                                                                | Out-of-order fixes must not drive geofence state backwards; the 1 h escape hatch avoids getting stuck after a flight.                                                                                |
| 8   | **Storage minimisation**: only the current position per person is stored (no track history). The event log keeps rounded distances and no coordinates; it is purged after `EVENT_RETENTION_DAYS` (30). `GET /v1/persons` rounds to 3 decimals. `DELETE /v1/location?person=` erases everything about a person.                                                                                                   | Privacy rules from `CLAUDE.md`; nothing in the requirements needs a track.                                                                                                                           |
| 9   | **Notion sync runs in-process on a timer** (no BullMQ, no Redis). Items are cached in `notion_items`; rules use the cache even when Notion is down and the event reason notes a stale cache.                                                                                                                                                                                                                     | One process, one container; a 5-minute sync of a small database does not justify a queue.                                                                                                            |
| 10  | **Notion API 2025-09-03 (data sources)**: the configured database id is resolved to its first data source; schema and queries use `data_sources/*`.                                                                                                                                                                                                                                                              | Current API version required by `@notionhq/client` v5; databases can contain several data sources, the first is the classic one.                                                                     |
| 11  | **Home Assistant zones are managed over the WebSocket API** (`zone/list                                                                                                                                                                                                                                                                                                                                          | create                                                                                                                                                                                               | update | delete`), not REST. Zone name = `HA_ZONE_PREFIX + place name` (`GR Lidl`→`zone.gr_lidl`). Only active places are mirrored; inactive/deleted places remove their zone; a warning is raised above `HA_ZONE_WARN_LIMIT` (20) active places. | The REST states API cannot create persistent zones; HA's zone collection is only writable over WebSocket. |
| 12  | **Zone events accept `zone` or `place_id`**: `POST /v1/geofence/events` resolves `zone` from the entity id, the zone friendly name (the `device_tracker` state), or the place name.                                                                                                                                                                                                                              | Lets the HA automation forward `trigger.to_state.state` without knowing GeoReminder ids.                                                                                                             |
| 13  | **Channel abstraction**: `NotificationChannel { send, test, listTargets? }` with a Home Assistant implementation and an FCM placeholder. Channel secrets (HA token, FCM service account) are AES-256-GCM encrypted with `ENCRYPTION_KEY`; the API never returns them.                                                                                                                                            | The only abstraction requested; FCM slots in without touching the evaluator.                                                                                                                         |
| 14  | **Auth**: `x-api-key` (or `Authorization: Bearer`) for machine clients with full access; admin UI uses a JWT in an httpOnly cookie issued by `POST /v1/auth/login` against `ADMIN_USERNAME/ADMIN_PASSWORD`. Single admin user.                                                                                                                                                                                   | One family, one admin; an identity provider would be over-engineering.                                                                                                                               |
| 15  | **Rate limits**: 600 req/min per IP globally, 60/min on `/v1/nearby`, 10/min on login, and one accepted `POST /v1/location` per person per `LOCATION_MIN_INTERVAL_SECONDS` (5 s; a batch counts once).                                                                                                                                                                                                           | Per-person throttling needs the parsed body, so it lives in the ingestion service rather than the IP-based plugin.                                                                                   |
| 16  | **Admin UI served by nginx** (`nginxinc/nginx-unprivileged`), `/api/` proxied to the API container. MapLibre GL with OpenStreetMap raster tiles (`VITE_TILE_URL` to switch), Nominatim proxied through the API (User-Agent, 1 req/s, cached). Plain CSS instead of a component library.                                                                                                                          | Keeps the API image free of static assets and lets HTTPS/hostnames be handled by the existing reverse proxy; the UI is small enough that a component library would add more build weight than value. |
| 17  | **Docker**: multi-stage `node:22-alpine`, non-root, multi-arch (amd64 + arm64 for the Raspberry Pi pre-production host). Images published to GHCR by GitHub Actions on every push (`pre` for `main`, plus branch and short-SHA tags). The compose file pulls images; `docker-compose.dev.yml` builds locally; `docker-compose.homelab.yml` attaches to an external network when Home Assistant is containerised. | The pre-production host is a Pi 4 (arm64, Docker 20.10) managed by Portainer, so no build step may be required there.                                                                                |
| 18  | **Home Assistant is not on the Docker network** in the target homelab (HAOS VM at 192.168.1.119). The API is published on a host port; HA calls `http://192.168.1.111:3000`, the API calls `http://192.168.1.119:8123`.                                                                                                                                                                                          | Reality of the deployment; the external-network overlay stays available for other setups.                                                                                                            |
| 19  | **Timezone**: containers get `TZ` (default `Europe/Bucharest`); the API also sets `process.env.TZ` from config.                                                                                                                                                                                                                                                                                                  | Matches the homelab standing rule; time windows must be evaluated in local time.                                                                                                                     |
| 20  | **Tests**: unit (domain logic, crypto, schemas) + integration against `imresamu/postgis:16-3.5` via testcontainers, covering approach, hysteresis, cooldown, daily cap, time window, missing Notion, zone events, plausibility and HTTP auth/validation. No spatial mocks.                                                                                                                                       | Required by the brief; the spatial query is the core.                                                                                                                                                |
